# App Shell

`AppShell.Root` installs controller context, application lifecycle, keyboard
dispatch, drag state, theme overrides, and active-surface tracking. Its
infrastructure overlays and popout host are enabled by default and can be
disabled with `renderOverlays` or `renderPopouts` for explicit composition.

## Structure

Use `AppShell.Surface` for the default desktop composition. For explicit
composition, keep `Ribbon` beside `DesktopLayout`; place `LeftSidebar`, `Main`,
`RightSidebar`, and `BottomPanel` inside `DesktopLayout`, and keep
`FloatingLayer` and `StatusBar` under the root. `Main` owns the center
`Workspace`, while `DesktopLayout` places the bottom panel across the selected
workspace columns. Omitting or replacing a surface does not change controller
behavior.

`DesktopLayout` and `Surface` accept `bottomPanelAlignment` with `left`,
`right`, `center`, or `justify`. An explicit prop overrides the controller-owned
`workspace.bottomPanel.alignment` setting; otherwise the setting defaults to
`center`. `Justify` spans the left sidebar, center, and right sidebar while the
ribbon remains full height.

The rendered body, left sidebar, right sidebar, and bottom panel carry stable
`data-workspace-surface` values. Design-core uses those destination surfaces to
resolve the public Workspace view background and foreground tokens, so normal
consumer views do not need placement selectors. A dragged view adopts its new
surface styling without runtime workspace-parent inspection.

Utility surfaces are also composable: `About`, `CommandPalette`, `Notices`,
`PluginLayer`, `Tabs`, `Sidebar`, `Settings`, `SettingsDialog`, `HotkeySettings`, and
`CorePluginsSettings`.

## API

- `Root` requires an `AppShellController` and optionally starts or disposes it.
- `Workspace` accepts an optional serializable tab factory.
- `BottomPanel` renders the controller-owned bottom dock and accepts the same
  optional tab factory.
- `DesktopLayout` provides the reusable three-column desktop grid for manual
  shell composition and bottom-panel alignment.
- `Surface` composes the current default desktop surfaces, a workspace footer
  with the settings trigger, and the controller-backed settings dialog.
- `Surface` accepts `workspaceLabel`, `settingsTitle`, and an optional
  `bottomPanelAlignment` override to configure that integrated application
  chrome.
- `AppWorkspace.bottomPanelAlignment` reads the configured alignment and
  `setBottomPanelAlignment()` updates it at runtime.
- `AppShellController.diagnostics` owns ephemeral diagnostic collections.
  Include `problemsPlugin()` when the application wants the standard movable
  Problems view and Show Problems command; resource navigation and fixes remain
  application adapters.
- `Settings` renders the controller-owned settings surface directly;
  `SettingsDialog` provides its reusable modal presentation.
- `Root` accepts an injectable popout host and explicit utility-layer toggles.
- Every lower-level component remains available through its own Workspace
  subpath.

All application state stays on the supplied controller; no global value is
installed.
