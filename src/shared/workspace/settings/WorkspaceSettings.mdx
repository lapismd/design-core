# Workspace settings

The settings family renders controller-owned configuration schemas using native
CSS and public Workspace tokens. It does not depend on Tailwind or shadcn
presentation primitives.

Applications can use the complete `WorkspaceSettingsSurface`, render
`AppShell.Settings` inside `AppShell.Root`, or assemble the compound parts:

{/* prettier-ignore */}
```tsx
<AppSettings.Root controller={app.settings} {app}>
  <AppSettings.Search />
  <AppSettings.Navigation />
  <AppSettings.Content />
</AppSettings.Root>
```

## Controller-owned settings

The built-in application controller contributes Appearance, Workspace,
Hotkeys, and Core Plugins. Updating a rendered field writes through
`WorkspaceSettingsController`, emits a typed change event, and requests a
debounced save through the configured persistence adapter.

## Presentation tokens

The default Lapis presentation reads the following Workspace tokens. Override
them on an ancestor of the settings surface or dialog:

| Token                                           | Default    |
| ----------------------------------------------- | ---------- |
| `--ui-workspace-settings-heading-size`          | `1rem`     |
| `--ui-workspace-settings-heading-weight`        | `400`      |
| `--ui-workspace-settings-label-size`            | `.9375rem` |
| `--ui-workspace-settings-description-size`      | `.75rem`   |
| `--ui-workspace-settings-navigation-row-height` | `2rem`     |
| `--ui-workspace-settings-control-height`        | `1.875rem` |
| `--ui-workspace-settings-control-radius`        | `.375rem`  |
| `--ui-workspace-settings-dialog-radius`         | `.5rem`    |
| `--ui-workspace-settings-dialog-max-width`      | `68.75rem` |
| `--ui-workspace-settings-dialog-height`         | `85vh`     |
