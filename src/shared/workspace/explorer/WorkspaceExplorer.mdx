# Workspace Explorer

`WorkspaceExplorer` is a controller-driven hierarchical file/folder panel for
workspace sidebars and registered views. It owns tree chrome, selection,
expand/sort/reveal UX, built-in menus, and HTML5 drop affordances. It does
**not** own vaults, filesystems, link rewriting, or native OS file actions.

Import from `@lapismd/design-core/workspace/explorer`.

```svelte
<script lang="ts">
  import {
    WorkspaceExplorer,
    ExplorerController,
    createMemoryExplorerAdapter,
  } from "@lapismd/design-core/workspace/explorer";

  const memory = createMemoryExplorerAdapter(/* seed nodes */);
  const controller = new ExplorerController({
    tree: memory.tree,
    actions: memory.actions,
    selection: memory.selection,
    preferences: memory.preferences,
  });
</script>

<WorkspaceExplorer {controller} />
```

## Boundary / ownership

| Concern | Owner |
| --- | --- |
| Tree chrome, expand/collapse, sort UI, reveal flash, row selection UI | Framework (`ExplorerController` + `WorkspaceExplorer`) |
| Built-in menus (new note/folder, copy vault path, rename, refresh, delete) | Framework |
| HTML5 file→folder drop highlighting and move/import calls | Framework |
| Listing entries + change subscription | Consumer `ExplorerTreeAdapter` |
| Create / rename / move / delete / open / optional external import | Consumer `ExplorerActionsAdapter` |
| Untitled naming, note-link rewrites | Consumer (for Lapis: vault + `fileManager.renameFile`) |
| Active-file sync + auto-reveal source path | Consumer `ExplorerSelectionAdapter` |
| Persist auto-reveal (`workspace.fileExplorer.autoRevealCurrentFile`) | Consumer `ExplorerPreferencesAdapter` |
| Native path / reveal in Finder / Lapis URL / `file-menu` plugins | Consumer via `buildItemMenu` |
| Empty-left-dock bootstrap leaf + host commands | Consumer / host plugin |

## Controller and adapters

```ts
new ExplorerController({
  tree,
  actions,
  selection?,      // optional active-path sync
  preferences?,    // optional auto-reveal persistence
  getIcon?,        // WorkspaceIcon name resolver
  buildItemMenu?,  // append after built-ins; source is always "explorer"
  onFileDragStart?,
  labels?,
  loading?,
});

controller.revealPath(path);
controller.setSelectedPath(path);
controller.refresh();
controller.setLoading(false);
```

`createMemoryExplorerAdapter(seed)` returns `{ tree, actions, selection, preferences }`
for stories and unit tests. `createExplorerViewDefinition` / `EXPLORER_VIEW_TYPE`
(`"file:explorer"`) help hosts register a leaf later without baking plugin code
into design-core.

## Surface anatomy

- Toolbar: create file, create folder, sort, auto-reveal, expand/collapse-all
- Group label (“Files”)
- Recursive tree rows with icons (`WorkspaceIcon` / `getIcon`)
- Loading gate (“Opening vault”) while `controller.loading` is true

The explorer root is borderless. Story canvases may draw a host border for
framing; pages that embed the panel own any chrome border. Tree scrolling uses
shadcn `ScrollArea` (not a native overflow container). The scrollbar stays flush
to the panel edge (Lapis `ScrollArea` is `h-full w-full` with no outer padding);
tree content is inset via `--ui-workspace-explorer-content-padding` (Lapis
`Sidebar.Group` `p-2`).

## Toolbar contract

- **Create file / folder** — call adapter create helpers; select the new path;
  folders enter rename mode; files also invoke `openFile`.
- **Sort** — filename A→Z / Z→A; folders always before files inside each folder.
- **Auto-reveal** — toolbar `aria-pressed` mirrors preferences adapter; when
  enabled, selection updates expand ancestors and scroll the active path.
- **Toggle collapse** — expand all folders or collapse all.
- Icon actions use shadcn `Tooltip` (`side="bottom"`) with the same label text as
  `aria-label` (sort shows the active sort mode).

## Tree interactions

- Click file → `actions.openFile`
- Folder expand/collapse via Bits Collapsible
- Click empty space in the tree body → root selection (`selectedPath ""`);
  create file/folder then targets the vault root
- Drop onto empty body space → move/import into the vault root
- Enter on a focused row starts inline rename; blur/Enter commits through
  `actions.rename`
- Delete is offered for files and **empty** folders only

## Menus

Built-ins (via `WorkspaceMenu` + `WorkspaceContextMenuItems`):

- New note / New folder
- Copy Path → From vault folder (vault-relative path only)
- Rename… (non-root)
- Refresh
- Delete (when allowed)

Hosts append native desktop actions, Lapis URLs, and plugin `file-menu` items
with `buildItemMenu(menu, node, "explorer")`. Mobile drawer presentation is a
host concern when embedding in Lapis.

## Drag and drop

Explorer file moves use **custom HTML5** DnD (`text/plain` path payload), not
layout `WorkspaceDragState` / drop-overlay and not dnd-kit. Dropping a file
onto a folder calls `actions.move`. External OS files call optional
`importExternalFiles`. Hosts that also drag into the shell can listen via
`onFileDragStart`.

## Preferences and configuration

The preferences adapter maps to Lapis
`workspace.fileExplorer.autoRevealCurrentFile` (boolean, default `false`). When
a host wires both the explorer toolbar and Workspace settings, both surfaces
must read/write the same key.

## Commands and reveal

Framework API: `controller.revealPath(path)` expands ancestors, selects the
path, scrolls into view, and applies a short flash. Recommended Lapis host
command ids for parity:

- `file-explorer:reveal-path`
- `file-explorer:show-file-explorer`

## Lapis adoption checklist

When wiring `packages/workspace` file-explorer onto this family:

1. Implement `ExplorerTreeAdapter` over `app.vault.getAllLoadedFiles()` +
   create/rename/delete events.
2. Implement `ExplorerActionsAdapter` with `openFile`, vault create helpers,
   `fileManager.renameFile` for rename/move, and vault delete.
3. Wire `ExplorerSelectionAdapter` to `active-leaf-change` / `FileView`.
4. Wire `ExplorerPreferencesAdapter` to
   `workspace.fileExplorer.autoRevealCurrentFile`.
5. Use `buildItemMenu` for system path, Lapis URL, native open/reveal, and
   `workspace.dispatch("file-menu", …, "file-explorer")`.
6. Mount `<WorkspaceExplorer {controller} />` from a thin `file:explorer` View;
   forward `revealPath` from the View/commands.
7. Keep empty-left-dock bootstrap and “Opening vault” loading in the host
   plugin (`controller.setLoading`).

## Intentional deviations from Lapis bundled explorer

- Native system path / OS reveal / Lapis URL are **not** hardcoded; hosts add
  them through `buildItemMenu`.
- Layout shell DnD remains separate; explorer file DnD stays HTML5-only.
- No Lapis `App` / `TFile` types in design-core.
