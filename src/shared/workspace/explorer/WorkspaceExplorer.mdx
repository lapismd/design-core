# Workspace Explorer

`WorkspaceExplorer` is a controller-driven hierarchical file/folder panel for
workspace sidebars and registered views. It owns tree chrome, selection,
expand/sort/reveal UX, built-in menus, and HTML5 drop affordances. It does
**not** own vaults, filesystems, link rewriting, or native OS file actions.

Import from `@lapismd/design-core/workspace/explorer`.

## Controller and adapters

<Source language="ts" code={exampleSources.ControllerApi} />

`createMemoryExplorerAdapter(seed)` returns an object with `tree`, `actions`,
`selection`, and `preferences` for stories and unit tests.
`createExplorerViewDefinition` / `EXPLORER_VIEW_TYPE` (`"file:explorer"`) help
hosts register a leaf later without baking plugin code into design-core.

## Surface anatomy

- Toolbar: create file, create folder, sort, auto-reveal, show hidden files, expand/collapse-all
- Accessible tree label (“Files”) without a redundant visible group heading
- Recursive tree rows with icons (`WorkspaceIcon` / `getIcon`)
- Loading gate (“Opening vault”) while `controller.loading` is true

<Canvas of={Stories.LoadedTree} />

The explorer root is borderless. Story canvases may draw a host border for
framing; pages that embed the panel own any chrome border. Tree scrolling uses
shadcn `ScrollArea` (not a native overflow container). The scrollbar stays flush
to the panel edge (Lapis `ScrollArea` is `h-full w-full` with no outer padding);
tree content is inset via `--ui-workspace-explorer-content-padding` (Lapis
`Sidebar.Group` `p-2`).

The explorer root and toolbar paint from
`--ui-workspace-view-background` and `--ui-workspace-view-foreground`. Moving
the registered view therefore follows the standard workspace surface contract:
direct left/right sidebars use panel paint, while body, bottom, grouped,
floating, mobile, and standalone placements use workspace paint. Explorer
consumers must not add placement selectors or cache layout ancestry.

## Toolbar contract

- **Create file / folder** — call adapter create helpers; select the new path;
  folders enter rename mode; files also invoke `openFile`.
- **Sort** — filename A→Z / Z→A; folders always before files inside each folder.
- **Auto-reveal** — toolbar `aria-pressed` mirrors preferences adapter; when
  enabled, selection updates expand ancestors and scroll the active path. The
  reveal flash runs only when the active file changes from outside the tree
  (tab switches, commands), not after a click that already selected that row.
  Its pressed glyph uses the theme's workspace accent foreground.
- **Toggle collapse** — expand all folders or collapse all.
- Icon actions use shadcn `Tooltip` (`side="bottom"`) with the same label text as
  `aria-label` (sort shows the active sort mode).

## Tree interactions

- Click file → `actions.openFile(path, { disposition: "current" })`
- Double-click file →
  `actions.openFile(path, { disposition: "reveal-or-new-tab" })`
- Ctrl/Cmd-click or middle-click file →
  `actions.openFile(path, { disposition: "new-tab" })`
- Folder expand/collapse via Bits Collapsible
- Click empty space in the tree body → root selection (`selectedPath ""`);
  create file/folder then targets the vault root
- Drop onto empty body space → move/import into the vault root
- Enter on a selected row starts inline rename; blur/Enter commits through
  `actions.rename`. Single-click keeps keyboard focus on that row after the
  `current` open so Enter still reaches the tree.
- Delete is offered for files and **empty** folders only

## Menus

Built-ins (via `WorkspaceMenu` + `WorkspaceContextMenuItems`):

- New note / New folder
- Copy Path → From vault folder (vault-relative path only)
- Rename… (non-root)
- Refresh
- Delete (when allowed)

## Drag and drop

Explorer file moves use **custom HTML5** DnD (`text/plain` path payload), not
layout `WorkspaceDragState` / drop-overlay and not dnd-kit. Dropping a file
onto a folder calls `actions.move`. External OS files call optional
`importExternalFiles`. Hosts that also drag into the shell can listen via
`onFileDragStart`.

## Preferences and configuration

The preferences adapter maps to Lapis
`workspace.fileExplorer.autoRevealCurrentFile` (boolean, default `false`) and
`workspace.fileExplorer.showHiddenFiles` (boolean, default `false`). When a
host wires both the explorer toolbar and Workspace settings, both surfaces
must read/write the same keys. Show hidden files reveals every dotted name,
including `.obsidian`, `.trash`, and `.lapis`.

## Commands and reveal

Framework API: `controller.revealPath(path)` expands ancestors, selects the
path, scrolls into view, and applies a short flash. Pass `{ flash: false }`
to keep the scroll/expand without the ring. Recommended Lapis host
command ids for parity:

- `file-explorer:reveal-path`
- `file-explorer:show-file-explorer`
- `file-explorer:toggle-hidden-files`

Nested folders draw a vertical indentation guide on
`.ui-workspace-explorer__sublist` (`border-inline-start`) using the guide
tokens above — the same role as Lapis `--nav-indentation-guide-*` / shadcn
sidebar `menu-sub` left border. The guide is centered on the expanded
disclosure chevron tip. The sublist also keeps
`--ui-workspace-explorer-folder-gap` after the folder row so a selected
folder wash does not touch the first child's hover wash.

## Lapis adoption checklist

When wiring `packages/workspace` file-explorer onto this family:

1. Implement `ExplorerTreeAdapter` over `app.vault.getAllLoadedFiles()` +
   create/rename/delete events.
2. Implement `ExplorerActionsAdapter` with disposition-aware `openFile`, vault
   create helpers, `fileManager.renameFile` for rename/move, and vault delete.
3. Wire `ExplorerSelectionAdapter` to `active-leaf-change` / `FileView`.
4. Wire `ExplorerPreferencesAdapter` to
   `workspace.fileExplorer.autoRevealCurrentFile`.
5. Use `buildItemMenu` for system path, Lapis URL, native open/reveal, and
   `workspace.dispatch("file-menu", …, "file-explorer")`.
6. Mount `WorkspaceExplorer` with the host `controller` from a thin
   `file:explorer` View; forward `revealPath` from the View/commands.
7. Keep empty-left-dock bootstrap and “Opening vault” loading in the host
   plugin (`controller.setLoading`).

## Intentional deviations from Lapis bundled explorer

- Native system path / OS reveal / Lapis URL are **not** hardcoded; hosts add
  them through `buildItemMenu`.
- Layout shell DnD remains separate; explorer file DnD stays HTML5-only.
- No Lapis `App` / `TFile` types in design-core.
