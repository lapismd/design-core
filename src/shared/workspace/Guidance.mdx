# Workspace

The Workspace layer provides a reusable application shell with recursive tabs
and splits, sidebars, floating windows, mobile presentation, settings,
commands, static plugins, and controller-owned persistence.

## Boundary

Workspace is a framework, not an application. Consumers provide views,
resources, persistence adapters, commands, and statically configured plugins.
The layer does not own routes, filesystems, vaults, editors, or dynamic plugin
discovery.

## Imports

```ts
import {
  AppShell,
  AppShellController,
  WorkspaceView,
} from "@lapismd/design-core/workspace";

import { WorkspaceCommandPalette } from "@lapismd/design-core/workspace/command-palette";
import { WorkspacePopoutSurface } from "@lapismd/design-core/workspace/popout";
import { WorkspaceTabs } from "@lapismd/design-core/workspace/tabs";
```

Every top-level Workspace component family with a public barrel has a matching
package subpath. Optional plugins are available from
`@lapismd/design-core/workspace/plugins/fmode` and
`@lapismd/design-core/workspace/plugins/notifications`.

## Styling

Workspace components use colocated native CSS and public
`--ui-workspace-*` tokens. Override tokens on an ancestor. Do not pass Tailwind
utility strings to component props.

Controls painted on `--ui-workspace-panel` use
`--ui-workspace-panel-action-hover-background` and
`--ui-workspace-panel-action-hover-foreground`. Their defaults bind to the
host theme's `--sidebar-accent*` semantics so hover feedback stays distinct
from the sidebar surface.
