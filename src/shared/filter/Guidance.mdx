# Filter guidance

Use `@lapismd/design-core/filter` for search chrome and the structured filter-query
language. Forms still own labelled rows and option pickers
(`FilterCommandPicker`); compose them with `SearchFilterBar` or `PowerSearch`
when a list or sidebar needs facets plus structured filters.

Offline agent summary: `pnpm ui guide layers`. Catalog components:
`pnpm ui components filter/search-filter-bar`,
`pnpm ui components filter/power-search`.

## Layer boundary

| Need                                    | Package                                         |
| --------------------------------------- | ----------------------------------------------- |
| Structured multi-field filters, no QL   | `PowerSearch` (`@lapismd/design-core/filter`)          |
| Search pill, clear chrome, filter slots | `SearchFilterBar` (`@lapismd/design-core/filter`)      |
| Parse / highlight filter queries        | `parseFilterQuery`, `filterQuery()`             |
| Field → operator → value completions    | Host `SearchFilterSyntax` + `filterSyntax` prop |
| Facet pickers (type, account, …)        | forms `FilterCommandPicker`                     |
| Matching rows against a ledger          | App / domain package (not in this UI package)   |

## Choosing a search surface

| Need                                              | Use                              |
| ------------------------------------------------- | -------------------------------- |
| Structured multi-field filters, no query language | **PowerSearch**                  |
| Free-text only                                    | `SearchFilterBar` `plain`        |
| Typed filter-query string + Lezer/CM              | `SearchFilterBar` `filter-query` |
| Facet pickers outside the bar                     | forms `FilterCommandPicker`      |

## PowerSearch

Controlled `tokens: PowerSearchToken[]` (field + operator + value). Combobox
adds fields; chips open the shared predicate editor; optional
`contentSearchFieldKey` commits free-text Enter as a token. Optional
`tokensToFilterQuery` serializes to a space-joined filter-query string for hosts
that still call `parseFilterQuery`. No CodeMirror.

## SearchFilterBar modes

- **`plain` (default)** — normal `<input type="search">` for free-text search
- **`filter-query`** — single-line CodeMirror editor with syntax highlighting;
  pass `filterSyntax` for autocomplete and the expandable syntax help panel.
  Completion tooltips reuse shadcn Command / Popover tokens (`--popover`,
  `--accent`, `--radius`, …), not CodeMirror’s default monospace/blue chrome.
  Completed `field op value` terms (Lezer `TermExpr`) render as removable
  inline chips with syntax highlighting once the value is non-empty and the
  caret is outside the term; click a chip to edit it. Field `valueKind`
  (`text` | `enum` | `number` | `boolean` | `date`) picks the chip-editor
  control; optional `ValueEditor` lets the host supply a custom component
  (forms `DatePicker`, ranges, etc.). Filter does not import forms.

## Filter query language

Boolean / grouping:

- AND: space, `and`, `AND`, `&&`
- OR: `,`, `or`, `OR`, `||`
- NOT: `-`, `not`, `NOT`
- Grouping: `(...)`

Operators: `:`, `>`, `=`, `<`, `!=`, `>=`, `<=`, `~`, `!~`

Values / tokens:

- `#tag`, `^link`
- Account-style names (`Assets:Cash`)
- Quoted strings `'...'` / `"..."`
- Regex `/pattern/flags`
- Field terms: `payee:"x"`, `amount > 100`, `account:Expenses:Food`
- Bare text (free-text search when the host evaluates it)

Dates / relative time (parsed by `parseFilterQuery`):

- Absolute: `2015`, `2012-Q1`, `2010-10`, `2016-W12`, `2015-06-12`
- Relative: `now`, `today`, `year`, `month`, `week`, `day`, `quarter`
- Arithmetic: `year-1`, `now-1w`, `2010 - 2012-10`
- Round: `now/month`
- Parens for literal day-of-month: `(month)-10`

### Host-owned completion schema

```ts
import type { SearchFilterSyntax } from "@lapismd/design-core/filter";

const syntax: SearchFilterSyntax = {
  description: "Narrow ledger directives.",
  fields: [
    {
      name: "account",
      description: "Any account on the entry.",
      operators: [":", "=", "~"],
      valueKind: "text",
      values: ["Assets:Cash", "Expenses:Food"],
    },
    {
      name: "amount",
      description: "Absolute units amount.",
      operators: [">", ">=", "<", "<=", "="],
      valueKind: "number",
    },
  ],
  examples: [{ query: "account:Expenses", description: "Expense accounts" }],
};
```

`valueKind` selects the chip-editor control (`text` with autocomplete,
`enum`, `number`, `boolean`, `date`). Optional per-field `ValueEditor` overrides
that with a host component (forms DatePicker, custom range, …). Range is not a
built-in kind — supply `ValueEditor`.

The bar only renders and completes this display model. Field catalogs and
match/evaluation stay in the app.

### Known grammar gaps

`any(...)` / `all(...)` posting-level matches are not implemented in the
Lezer grammar shipped here.
