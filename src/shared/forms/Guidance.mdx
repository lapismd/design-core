# Form guidance

Use `@lapismd/design-core/forms` for structured editing and CV form-row chrome. Use
shadcn for generic controls (`Select`, `Switch`, `Command`, `Input`, …).

This page mirrors the CV Studio forms contract (`forms-and-shared-ui`) and the
package `FORMS.md`. Offline agent summary: `pnpm ui guide forms`. Each
component Docs page adds when/when-not guidance, usage, properties, and
variations.

For a full application-shaped composition, see
[Complete CV Form](?path=/story/ui-forms-examples-complete-cv-form--interactive-sample-cv).
It combines the body-only App Shell, form toolbar, tabs, every CV entry type,
Design/Locale/Settings groups, and persistent live fragment YAML beside the
structured form without introducing a CV-specific package component.

## Choose the right layer

1. **StructuredForm** — schema-shaped data with path-keyed configs from
   `defineFormConfig<TValues>()`. Paths, kinds, defaults, validators, and array
   factories are checked against the value model. The callback-based
   `createFormConfig` builders remain available for manual adapters.
2. **Composed primitives** — `FormField`, `FormSectionHeader`,
   `CollapsibleItemList`, `InlineOptionPicker` for one-off layouts.
3. **YamlBackedForm** — dual structured + YAML source mode over the same draft.
4. **JsonBackedForm** — dual structured + JSON source mode (prefer YAML for new
   user-authored config).
5. **PatchableForm** — YamlBackedForm + JSON Patch Keep/Undo review
   (`createOrAppendJsonReview`, reviewed field builders, YAML `toYamlDiffs`).
6. **shadcn** — Select, Switch, Command/Popover pickers, Toggle Group, Field.

## Shared form pattern

Default editable forms should be minimal and row-based:

- labels on the left
- editable values on the right
- visible row separators
- proper-case labels and section titles
- debounced autosave unless a workflow has a reason to defer writes

Compose fields inside one `max-content minmax(0, 1fr)` label/value grid per
form scope (`cv-structured-form` / `ui-structured-form`). Do not invent
arbitrary flex rows for labelled fields.

For large forms, keep the consumer boundary controlled: pass `value`,
`onChange`, and optionally `createFormController<TValues>()`. The controller
owns dirty/touched/validation, focus, repeat identities, and disclosure state;
the application still owns persistence and authoritative values. Use an
explicit `createFormRendererRegistry()` for downstream field kinds so renderer
registration remains isolated across forms and SSR requests.

## Tokens

`@lapismd/design-core/forms/tokens`), with defaults in `form.tokens.css` mapped to
theme tokens. Paint via colocated component CSS — no Tailwind utilities in form
sources. Override on `:root` or a form ancestor — same idea as wired shadcn
`--ui-<family>-*` maps. Each component Docs page includes a **Style** table of
the tokens that family reads.

## Sections and repeatable groups

- Use **FormSectionHeader** for top-level editable sections. Keep headers
  collapsible; expose move/delete on hover. When the title is not editable,
  set `titleToggleable` so the whole title row is the disclosure control.
- Disclosure toggles sit in an absolute left rail, not in the row grid.
- Use **EntryActions** for repeated entries that can be reordered or removed.
  Arrays whose order is persisted or shown must expose shared up/down controls
  unless order is domain-fixed.
- Use **CollapsibleItemList** when the header owns collapse state and count.
- Repeated entries that need their own editable title + disclosure use
  `FormSectionHeader`, not a bespoke heading/border combo.
- Empty arrays render no filler copy — the add affordance is enough.
- Add actions stay in the section footer, bottom-aligned. Newly added blank
  rows should use field-specific placeholders (e.g. `Add Technology`).
- Optional object groups share the same add flow as arrays.

## Layout checklist

1. Prefer `StructuredForm` for schema-shaped data; otherwise compose
   `FormSectionHeader`, `FormField`, and the shared repeatable-entry primitives.
2. One label/value grid per form scope; keep the form container `min-width: 0`.
3. Let `FormSectionHeader` own the single separator under a disclosure header.
   Wrappers and entry containers provide spacing/indentation only — no adjacent
   top/bottom borders.
4. Make every non-editable disclosure title-row clickable. Editable-title rows
   keep direct title editing and use the left-rail chevron to collapse.
5. Dotted outlines are **only** for story/demo stubs via `FormPlaceholder` —
   never for real package components. When a docs story needs a fake expanded
   body (e.g. under `FormSectionHeader`), wrap that sample copy in
   `FormPlaceholder`. `EntryActions` / `CollapsibleItemList` render children
   normally with no outline.
6. Verify expanded/collapsed layout (including nested collapse-all) and check
   for duplicate separators.

## Control choice

Consumers that need only the searchable filter selector may import
`FilterCommandPicker` and its option types from the focused
`@lapismd/design-core/forms/filter-command-picker` entry point. The forms
barrel remains available for broader form compositions.

| Need                   | Use                                                                            |
| ---------------------- | ------------------------------------------------------------------------------ |
| 2–3 exclusive values   | `SegmentedControl` (inside `FormField align="center" as="div"`)                |
| Larger option sets     | shadcn `Select`, or `InlineOptionPicker` for menu/swap + icons                 |
| Sequential options     | `CyclePicker`, or `options` with `presentation: "cycle"`                       |
| Color text + swatch    | `ColorPicker`, or a typed `color` field                                        |
| Multi-value tags       | `ChipAutocomplete` (`tagListField` / `chipListField`)                          |
| Ordered string lists   | `ListEditor` + `SortableArrayItem`                                             |
| Searchable choices     | `FilterCommandPicker` (options + optional `allowCustom` via props)             |
| Search / filter query  | `@lapismd/design-core/filter` `SearchFilterBar` (compose; see Filter/Guidance) |
| Dates                  | `DatePicker` (natural-language + `TaskDueCalendar` month grid)                 |
| Times                  | `TimePicker` (styled native `type="time"`; value `HH:mm`)                      |
| Pill / date controls   | `FormField align="center"`; popovers use `as="div"`                            |
| YAML source            | `YamlEditor` only — no plain textarea YAML editors                             |
| Code source            | `CodeEditor`                                                                   |
| Read-only source       | `CodeHighlighter` (Lezer parser + display-ready text)                          |
| Credentials            | `SecretField` (`env:NAME` or masked inline; host supplies env key names)       |
| Dual structured + YAML | `YamlBackedForm` (YAML edits the authoritative draft)                          |
| Dual structured + JSON | `JsonBackedForm` (compatibility path; prefer YAML for new drafts)              |
| Textareas              | Autosize, hide resize handles, avoid internal scroll for ordinary editing      |

`CodeEditor` and `YamlEditor` are the stable Design Core imports. They add
language, validation, YAML folding/formatting, and review behavior to Mira's
language-neutral `MiraCodeEditor`, which owns the CodeMirror lifecycle, shell,
and scroller. Theme them through form tokens; do not add consumer `.cm-*` shell
overrides or mount a second `EditorView`.

## Evidence references

`ReferencePicker` shows stored ref, resolved path, label, and excerpt.
Unresolved and duplicate refs stay visible. Markers (`[^id]`) are editor
metadata — generated Markdown/YAML/HTML must strip them.

## YAML and AI review

Document editors (CV, docs, practice) expose the same toolbar YAML switch.
Valid YAML updates the draft and autosaves; invalid YAML stays editable and
surfaces the parse error. Collapse/expand-all in YAML mode folds the active
CodeMirror editor.

When an AI proposal changes a form value, review mode shows the two line-aware
unified-diff versions (removed words struck through; additions emphasized).
YAML review uses the same two-version model.

Use **`PatchableForm`** with `createOrAppendJsonReview` for reusable Keep/Undo
orchestration over structured fields and `YamlEditor` hunks. Field configs should
use `reviewedTextField` / `reviewedStringListField` so pending JSON Pointer paths
wire into `FieldReviewContext`. Hosts supply `toYamlDiffs` for CodeMirror widgets.
Interaction stories live under **UI Forms/Orchestrators/Patchable Form** and **UI Forms/Editors/YAML Editor**.
