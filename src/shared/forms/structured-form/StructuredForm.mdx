# StructuredForm

Config-driven form runtime for schema-shaped data. Prefer a path-keyed typed
configuration over hand-rolled field lists when the value model is known.

Establishes the `cv-structured-form` host grid for label alignment.

## Guidance

### When to use

- Schema-shaped editing with `defineFormConfig<TValues>()`
- Typed groups, primitive and object arrays, and discriminated variant arrays
- Controlled values with controller-owned validation and disclosure metadata
- Existing callback builders through `createFormConfig`
- Shared validation issues + readonly/view modes

### When not to use

- One-off composed layouts — use `FormField` + section primitives directly
- YAML source editing — use `YamlBackedForm` / `YamlEditor`

See also [UI Forms/Guidance](?path=/docs/ui-forms-guidance--docs) and the shared form contract in `FORMS.md`.

{/* prettier-ignore */}
```tsx
<StructuredForm
  {config}
  value={profile}
  onChange={(next) => (profile = next)}
/>
```

Paths and renderer kinds are checked against the value at that path. Optional
and nullable paths select their renderer from the non-null value type. A
`defaultValue` is display-only: a missing optional key stays absent until that
field is edited.

Built-in string controls include `color` for a native swatch plus editable
source value, and `options` with `presentation: "cycle"` for compact
previous/current/next browsing. Set `optionPreview: "font"` when each option
should be displayed in its named font family.

## Controller

`createFormController<TValues>()` owns dirty, touched, validating, validation
issue, disclosure, repeat-item identity, focus, and reset metadata. It does not
own persistence or the authoritative form value.

```ts
const controller = createFormController<Profile>({ defaultValues: profile });
await controller.validate();
controller.focus("name");
controller.collapseAll();
```

Pass the controller explicitly with `{controller}`. Validation modes are
`onSubmit`, `onBlur`, `onChange`, `onTouched`, and `all`.

## Custom renderer kinds

Custom kinds are registered on a form-local registry. Registries are isolated;
registration never changes a process-global renderer table.

```ts
declare module "@lapismd/design-core/forms/core" {
  interface FormFieldKindMap {
    currency: FormFieldKindDefinition<number, { currency: string }>;
  }
}

const registry = createFormRendererRegistry();
const unregister = registry.register("currency", {
  component: CurrencyField,
});
```

Import `createFormRendererRegistry` from `@lapismd/design-core/forms`; import
`FormFieldKindDefinition` and `defineFormConfig` from
`@lapismd/design-core/forms/core`.

Use `<StructuredForm {registry} ... />`. A duplicate registration throws unless
`{ replace: true }` is passed; the returned disposer restores the previous
renderer. A missing renderer produces an accessible developer error.
