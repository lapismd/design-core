# Transcript

Continuous immutable conversations, with exact-range comments and host-owned delivery.
The default presentation retains jj-store’s document geometry. The caller owns the
controller so drafts survive presentation teardown. No component reads files or runs tools.

## Captured tool inspectors

Use `onInspectTool` to open host-owned chrome and render `TranscriptToolContent`
with the same controller inside it. The rootless content registers its exact
readers while the main Transcript retains its own scroll/navigation viewport.
Closing and restoring the opener remain host actions.
When an inspector shares a block with the main transcript, closing either reader
restores navigation to the surviving reader.

## Reference and tokens

Adapted from jj-store at `496045ad`, Apache-2.0, LapisMD contributors.
The 24px avatar column, 8px gap, compact source cards, folded captures and comment
queue retain the source presentation. Override `--ui-transcript-max-width`,
`--ui-transcript-font-size` and `--ui-transcript-line-height` when composing a host.
Rendered Markdown inherits its surrounding text size and uses zero additional
inset, including in rootless inspectors and standalone queues. Its tokens are
`--ui-transcript-markdown-padding` (0), `--ui-transcript-markdown-font-size` (1em),
`--ui-transcript-markdown-line-height` (1.55) and
`--ui-transcript-paragraph-spacing` (0.45rem). Editable comments use the bare
CommentComposer presentation inside the existing comment card.
Reply prose, quoted context and comment cards inherit the same host font and
foreground. Comments and their editors default to the transcript's prose size
(0.875rem), with `--ui-transcript-comment-font-size` available for an explicit
override. This replaces the earlier, larger 1rem default following visual review.

Document mode keeps the trailing document buffer after the inline draft: 4rem
on desktop and 3rem below 600px. Override
`--ui-transcript-composer-trailing-space` to change this writing space. Classic
keeps its existing 1rem composer inset, including when fixed.

Collapsed file, tool and context headers show only the last nonempty current root
comment per discussion. Expanding restores earlier comments; agent responses stay
in their linked messages. Historical versions remain in history.
Tool, file and reasoning disclosure rows share a compact rhythm: 24px minimum
height, 13px type and 4px between activity rows, with no extra inline baseline
space or taller hidden raw control. Override `--ui-transcript-tool-row-height`,
`--ui-transcript-tool-font-size` and `--ui-transcript-tool-row-gap` to adjust it.
Prose messages retain their separate paragraph and turn spacing.

Nested file headers lead with file/patch icons; reasoning uses the lightbulb
also used by jj-store's thinking control. Hosts can override item icons.

## Footer, waiting messages and author details

Use the `footer` snippet with the public `TranscriptFooter` to keep send controls
outside the scrolling document. It can read `state={controller}` or explicit
controlled props. Idle content shows Send; busy content shows Queue; busy empty
content shows Stop when the host supplies `onStop`. Pending delivery can retain
a separate stop button. A persistent `onStop` callback does not imply busy state.
Send uses the paper-plane icon, Queue the upward arrow and Stop the square.
The full conversation simulates a confirmed stop by setting `busy` to false;
sending from idle starts another simulated response. The pending-stop example
retains its stopping state until host acknowledgement. Real hosts must update
`busy` from confirmed runtime state rather than assuming a stop request succeeded.
Callbacks request host actions and never imply delivery.
`actions`, `workspace` and `controls` snippets accept additional buttons and menus.
Set `showSendButton={false}` on MarkdownComposer to keep one send affordance.

Render `MessageQueue` in `queuedMessages` with exact submission snapshots and
recipient display states. Cancellation, status review and acknowledgement belong
to the host. Unknown outcomes retain their content and explanation. Long text
expands without changing the captured snapshot.

Set `authorPopover` to opt every transcript identity into the shared AuthorCard,
including messages, comments, queues, composer avatars and reply groups. Its
`interaction` defaults to `"popover"`; choose `"hover"` for profile previews.
The full conversation enables hover cards with host-supplied descriptions and
actions. Omitting `authorPopover` retains ordinary avatar presentation and group
name tooltips. The shared AvatarGroup also accepts a generic `avatar(person, size)`
snippet for AuthorCard composition outside Transcript.

Supply `onReact`, controlled `reactions` and optional custom/restricted emoji to
enable adding or toggling reactions, including with an external comment controller.
`authorPopover` supplies descriptions, a details snippet and configurable actions;
omitting it leaves avatars decorative. Shared Popover and ScrollArea handle
keyboard dismissal and focus restoration. Tool/group `icon` components are
explicit presentation inputs; provider interpretation remains in adapters.

## Recorded comparison

The full conversation story reuses jj-store's sanitized Delta session with 30
captured tools, assistant segments, and returned agent responses. Its review
comments and replies are the source's explicitly simulated overlay. Waiting
messages and footer/runtime choices are labelled demos. No agent is contacted.
The source projection and recording are catalog-only and are not packaged.
Its Document / Classic selector changes the controlled `view` on the same mounted
Transcript, items and comment controller. Readers, folds, raw/rich choices,
reactions, pending comments and queued messages retain their identities and data.
Use the composer snippet's applied view argument to choose `document` or `framed`
presentation on one MarkdownComposer. A view change during IME composition waits
until composition ends; the composer receives that applied view too.
The returned agent-response section starts open to expose its XML disclosure;
Chat / Prompt Context / Recorded agent context shows that exact capture directly
with rendered Markdown, independently of the long transcript.
See `spec/records/transcript-parity-audit.md` for provenance and the gap audit.

## Sent application context

Set `TranscriptItem.sentContext` with captured `content`, explicit `delivery` and
optional exact `rawContent`. The compact SentContext disclosure appears before
authored message blocks. Its delivery labels and raw/rendered UI match jj-store;
it never infers delivery or adds context to captured comment text. The full story
labels its unknown-delivery context as demonstration data.

## Reviewed parity refinements

Classic uses shared Message chrome with a 36px avatar, an author/role header and
hover surface. The same readers remain mounted in Document and Classic. Set
`--ui-transcript-classic-padding` to override Classic's 0.375rem row inset. Set
`timestamp` for display text and `createdAt` for an ISO date/full-date tooltip;
`edited`, `replyCount`, `replyLabel` and `replyParticipants` supply neutral metadata.
`onOpenThread(item)` requests host navigation. Metadata supplements remain available.
Reply participant summaries use the shared AvatarGroup at `xs` (20px), preserving
images, emoji, initials and shapes. Participant buttons retain their names and optional AuthorCards beside the separate reply button; the reply count owns its navigation
callback and keyboard activation. Hover underlines only the reply label; avatars remain undecorated
and the hovered participant rises above its neighbours.

Reply contexts use one outer padded border. Jump to end focuses the enabled
composer in the transcript's composer slot, falling back to the last item.
Set `submitOnEnter={false}` when both presentations should keep multiline Enter.
Use `dockActions` and `bind:documentActions` on MarkdownComposer, rendering the
bound snippet once in TranscriptFooter's `actions`; document actions are docked,
while Classic keeps its inline toolbar as in jj-store.

Enable sent-comment editing with `canEditComment(thread, comment)`. The controller
also requires a current authored sent/replied comment, `version`, and available
source. `editSent` creates or resumes a replacement draft; `onSend` receives its
`editOf` original comment ID, message ID and version. Keep persistence and version
conflict resolution in the host. Published results can return `commentVersions`
keyed by submitted comment ID. Only acknowledgement retires the exact replaced
version; queued/unknown/rejected changes retain it, and newer drafts are preserved.
Without a returned version, further editing waits for a host data refresh.

## Message outcomes

Set `item.status={{ type: "error", label: "Failed", message: "Your message is retained." }}`
to place status below the message body. The shared MessageMetadata row keeps the
time, `metadataSupplement` action buttons and outcome in that order. Supply retry
through the supplement; rendering or changing views never dispatches a retry.
Classic retains the same metadata and red error detail below its prompt.

Style metadata with `--ui-transcript-metadata-font-size` (0.75rem),
`--ui-transcript-metadata-gap` (0.4rem) and the shared
`--ui-ai-chat-metadata-error-foreground` (a readable semantic destructive/foreground mix).
Context, handoff and rootless content use `--ui-transcript-font-size` (0.875rem)
and the host sans font; the existing Markdown tokens retain independent spacing.

Retained unavailable-source comment cards use `--ui-transcript-stale-gap` (0.5rem)
between cards, keeping each status banner attached to its own captured quote.

Captured file headers and disclosures use the shared FileTypeIcon when `path` is supplied. Tool titles retain an explicit host icon or error/running indicator before falling back to the captured path icon. No filename is inferred from prose labels.

## Host references and actions

Use `markdown.references` and `inlineReferences={block => chatReferenceDecorations(block.text, references)}`
with the same host codec for preview and retained CodeMirror readers. Reader
hooks also apply with an externally owned TranscriptController.
`commentComposer` accepts the same reference codec, trigger suggestions and
CodeMirror extensions; comment previews use the transcript Markdown configuration.

`getMessageActions(messageId, block)` returns shared MessageAction descriptors.
Primary actions use icon buttons; other actions use the kebab menu alongside
Comment and optional reactions. The default Comment is icon-only, hidden bars
never intercept tool controls, and a wholly unavailable bar is omitted. Set
`actionTooltips={false}` to omit tooltips. The older messageActions snippet remains
available for custom host controls.

## Captured disclosure outcomes

Set `tone: "destructive"` on a captured context/reasoning/handoff item to render
its disclosure label and icon in readable red. This presentation does not turn a
permission decision into an execution error or change its captured content.
Final compact rows retain `--ui-transcript-tool-row-gap` (0.25rem) below them.
Inline draft comments use CommentComposer's T toggle and formatting strip.
