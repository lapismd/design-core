# Column Canvas

Horizontal, selection-driven column cascade for Miller-column / Finder-style
navigation. A typed app-owned controller owns path selection, durable widths,
and collapse/close. `Root` adapts its canvas presentation to its bounded width
without mutating that controller. Compound parts (`Header`, `Toggle`, `Close`,
`Body`, `Item`) provide consistent chrome so hosts do not invent row or header
styling.

This is a project-authored native-CSS family. It is not the same as
[Resizable](?path=/docs/shadcn-layout-resizable--docs): Resizable fills a box
with percentage pane groups, while Column Canvas grows a horizontally scrolling
canvas. Wide layouts prioritise the newest pair with a narrow preceding-column
context slice; compact layouts use one full-stage active column and mandatory
snapping.

## Usage

Always mount `Column` parts under `Root`. Configure each column’s `pathLevel`
so cascade visibility is controller-owned (same idea as AppShell self-gating
closed/collapsed chrome). Hosts map `path` keys to domain rows; they do not
`{#if}` columns into the tree. The primary demo is a realistic six-column
product workspace with a four-level path, two sticky leading lanes, and five
closeable downstream lanes. Use **Show code** on the preview for a
copy-pasteable example.

`Item` rows use `--ui-column-canvas-item-gap` (`0.25rem` by default) to keep
adjacent hover and selected surfaces visually separate.

## Configure the controller

Create one app-owned controller and pass it to `Root`. The controller owns the
selection path and durable layout state. Keep its reactive fields on the
controller object instead of destructuring them.

## Compose columns

Passing `title` to `Column` renders the standard `Header`, `Title`, `Count`,
`Toggle`, and `Close` chrome. Omit `title` when you need a custom header and
compose the exported parts yourself:

`Body` owns an independent vertical Scroll Area. Its `onScrollNearEnd` callback
fires whenever the body is within 180 CSS pixels of its bottom. Use it for
incremental loading. `Item` is a button that accepts native button attributes;
`selected` sets both `data-selected` and `aria-pressed`, while `disabled`
retains native button behavior.

The near-end callback can fire again while the body remains near its boundary.
Deduplicate in-flight loading in the host. `Toggle` and `Close` accept shared
Button props and render only when their controller capability is enabled. When
you omit `Column.title`, use readable column ids or override the action labels
as the custom example does.

### Compound context hooks

Use `useColumnCanvas()` inside a custom descendant to read the controller.
`useColumnCanvasContext()` also exposes the resolved display mode and layout
request functions for compound extensions. `useColumnCanvasColumn()` reads the
current column id, title, count, and capability flags inside `Column`. Do not
destructure reactive context getters.

## Responsive display

`displayMode="auto"` is the default. `Root` observes its own width and resolves
to `wide` at or above `compactBreakpoint` (`960` by default) or `compact` below
it. The resolved state is available as `data-display-mode`.

`Root` also forwards native div attributes and event handlers. An `onkeydown`
or `onwheel` handler can call `preventDefault()` before the built-in routing
logic runs.

- **wide**: the newest two rendered columns expand as needed to share the
  stage while retaining at least their durable pixel widths; when older context
  exists, `--ui-column-canvas-wide-context-width` remains visible; resize
  handles, an optional `trailingSpacerWidth`, active following, and proximity
  snapping remain; no trailing spacer is added by default
- **compact**: each expanded column occupies the complete bounded stage, with
  no previous-column peek, durable blank tail, horizontal scrollbar, or resize
  handles; mandatory snapping; and slower, smooth
  vertical-to-horizontal routing for non-scrollable columns and scrollable-body
  boundaries
- **fixed**: original fixed geometry and free horizontal scrolling at every
  size, without active following

Set `displayMode="compact"` to force the compact presentation at every root
width. Set `displayMode="fixed"` to bypass container adaptation. In auto mode,
`compactBreakpoint` uses the bounded root width rather than the viewport.

Responsive widths and scroll position are transient. V1 persistence continues
to contain durable width, collapse, and close state only.

## Sticky columns

Set `sticky` on consecutive leading `Column` parts to register separate
floating collapsed rails. The source columns always remain full-width in
normal flow. Once a source moves underneath its rail-width slot, the root shows
an opaque replacement rail while every source and following column continues
moving with native horizontal scrolling.

Supply a named `stickyRail` snippet to customize the contents of that floating
replacement's return button. `Root` composes a circular outlined shadcn `Button`
with the visible column label beneath it and owns the return behavior: clicking
it scrolls back to its source column without changing controller selection.
Without a snippet, the button uses the standard back arrow.

Sticky presentation applies in `wide` and `fixed` modes. Compact mode ignores
it and keeps the full-stage active-column presentation. Expanded sticky
columns use `--ui-column-canvas-sticky-peek-width` (the collapsed-column
`2.75rem` width by default) for their floating rail; collapsed sources use their
complete collapsed width.
Consecutive rails share one gapless stack, flush with the root inline and block
edges, so root padding and moving content cannot show around or between them. A
sticky request after the first non-sticky rendered column remains ordinary
flow. In wide and fixed sticky canvases, otherwise-unused vertical wheel input
over a non-scrollable body moves the horizontal track continuously; scrollable
bodies still consume the motion first, and canvas-edge motion remains available
to the surrounding page.

## Persist layout

`Root` calls `restoreLayout()` and exposes restoration through
`controller.layoutReady` and `data-layout-ready`. A persistence adapter loads
unknown data and saves the normalized V1 shape:

```json
{
  "version": 1,
  "columns": {
    "tasks": { "width": 380, "collapsed": false, "closed": false }
  }
}
```

V1 persists each registered column's width, collapsed state, and closed state.
Invalid versions and malformed entries are ignored. Restored widths are
clamped to the current `minWidth` and `maxWidth`.

Use `createLocalStorageColumnCanvasLayoutPersistence(key, storage?)` for browser
storage, or implement `ColumnCanvasLayoutPersistence` for another backend.
Call `flushSave()` before a host must observe pending changes. Call `dispose()`
when the owning application lifecycle ends.

`onLayoutChange` receives a `source` of `collapse`, `close`, `resize`,
`reset-width`, `register`, or `ensure`, plus the affected `columnId`.
`onPersistenceError` reports `load` and `save` failures without replacing app
error policy.

The selection path, `pathLevel`, responsive mode, sticky state, and scroll
position are transient. They never enter the V1 layout schema.

## Accessibility and input

`Root` defaults to a focusable `region` named “Column canvas”. Supply a
domain-specific `aria-label` when a page contains more than one canvas. Native
HTML attributes and event handlers pass through every visual part.

When compact `Root` itself has focus, Arrow Left, Arrow Right, Home, and End
move between snap points without changing controller selection or descendant
focus. Horizontal wheel, trackpad, and touch movement remain native. Vertical
wheel motion stays with the nearest scrollable body while it can move. Unused
vertical motion moves an eligible horizontal canvas, and motion at the canvas
edge remains available to the surrounding page.

Toggle, Close, collapsed rails, resize separators, and sticky return buttons
ship with accessible names. Routed scrolling uses instant motion when the
reader requests reduced motion. Logical inline-axis geometry supports
left-to-right and right-to-left documents.
