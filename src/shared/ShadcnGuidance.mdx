# Shadcn guidance

Use `@lapismd/design-core/shadcn/<family>` for generic primitives. Do **not** run the
upstream `shadcn-svelte` CLI against this package tree — use the local generator.

This page is the catalog companion to `pnpm ui guide shadcn` and `AGENTS.md`.
For the form decision guide, see **UI Forms/Guidance**.

## When to use shadcn

- Buttons, toggles, inputs, selects, dialogs, menus, layout chrome, feedback
- Shared visual language and `--ui-<family>-*` tokens across consumers
- Controls composed inside forms (Select, Switch, Command + Popover, Field)
- Inline **Code** and fenced **Code Block** presentation (`Shadcn/Content/…`).
  Prefer these over Forms `CodeHighlighter` when you have a language string
  rather than a Lezer parser. See `spec/records/code-and-code-block.md`.

## Customization

Converted families paint from **CSS custom properties**, not Tailwind `cn()` /
utility class merges (those were compile-time inputs to `ui:add`).

1. **Theme** — override shared `--primary`, `--radius`, etc. in `theme.css` or on
   a host ancestor for global brand.
2. **Family tokens** — override `--ui-<family>-*` (defaults in
   `<family>.tokens.css`, names in `<family>.tokens.ts`). Example: set
   `--ui-button-background` on a subtree to restyle primary buttons without
   changing `--primary` for the whole app. Import maps from
   `@lapismd/design-core/shadcn/<family>` or `@lapismd/design-core/shadcn/button/tokens`.
3. **Do not** reintroduce Tailwind utility class strings into shared or
   converted component sources. `pnpm check:no-tailwind` (part of
   `pnpm checks`) enforces this. Prefer tokens and scoped CSS.

Same override idea as forms (`--ui-form-*` / `form.tokens.css`).

## Trigger overlay documents

Popover, Hover Card, Tooltip, Dropdown Menu, Context Menu, and Select follow
their trigger's `ownerDocument` automatically. This keeps overlays inside a
browser popout while allowing normal in-page overlays to portal to that
document's body and escape a constrained pane. The resolution order is:

1. explicit `portalProps` supplied by the consumer;
2. inline rendering under an overlay host such as `WorkspacePopoutSurface`;
3. the same-document trigger body;
4. the underlying Bits UI default.

A target from another Window realm is never passed to Bits UI; the family
falls back to inline rendering. Consumers should use `portalProps` only for an
intentional host override and must not recreate owner-document detection or
manual anchors. Hover Card retains the Bits UI `LinkPreview` defaults (700ms
open, 300ms close) and its safe pointer corridor. Its elevated layer is
controlled by `--ui-hover-card-z-index`.

## When not to use shadcn alone

- Schema-shaped editing / label-value form rows → `@lapismd/design-core/forms`
- Shared AI chat primitives → `@lapismd/design-core/ai`

## Add or convert a family

1. Classify in `spec/src/component-inventory.md` if the boundary is unclear.
2. `pnpm ui:inspect <name>` — support tier and candidates (read-only).
3. `pnpm ui:add <name> [--overwrite] [--dry-run]` — transactional convert in a
   detached worktree. Batches: `pnpm ui:add:batch a|b|c|d`.
4. `pnpm ui:docs --component <name>` — sync vendored upstream docs into `*.docs.md` / MDX
   (`vendor/shadcn-svelte-docs`; refresh with `pnpm ui docs:vendor`).
5. Keep colocated stories under `Shadcn/...` with real interactive play coverage.
6. Verify with the testing workflow (`pnpm ui guide testing`).

Preserve `data-ui-component`, `data-ui-part`, `data-slot`, token metadata, and
`*.provenance.json`. Treat parity or unsupported conversion failures as hard
stops — do not copy registry files by hand.
