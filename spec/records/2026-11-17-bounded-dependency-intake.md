# Bounded dependency intake qualification

The schema2 source profile selects Mira, the Node-only specification validator
and Visual Delta. Architecture, Packages and Tooling retain factual managed
slots. The independent source guard checks real registry facts and compatible
forward patches, preserves public contracts and immutable versions, and rejects
unrelated source, routing, metadata, policy or release-intent changes. Fourteen
positive/rejection tests include the actual empty Changesets frontmatter and a
null-frontmatter rejection.

Ordinary quality, aggregate specification checks and pre-writer validation run
the independent guard. The reviewed runtime guard now determines genuine release
intent before both App credentials and Changesets, and both writers require true.
The actual Changesets 3 recipe, source helper and static qualification hashes
remain unchanged; the completion callback keeps its reviewed existing pin.

A real-registry controlled rehearsal starts at published validator 0.2.0 with no
notes and admits released 0.2.1 through reviewed coordinator v2 preparation and
the independent source guard. No-note Changesets status fails for this public
root. The actual coordinator-generated empty managed note then passes the guard,
reports false release intent, and permits the unchanged whole version macro to
exit 0 with version 0.13.5 unchanged. The coordinator therefore needs its explicit
emptyChangeset option for this repository. This is local controlled evidence;
live activation, publication and durable reconciliation/replay are separate.

Fourteen guard tests, all 62 release tests, three specification lanes, QMD and
doctor pass. Full source validation exercised 1133 unit cases, 1066 Storybook
interaction cases, static/metadata checks and Workspace/Shell/AI browser lanes.
The matching Ubuntu browser image passed the fourteen-case focused regression
selection. Its full Shadcn run has 193 passes, one governed skip and three failures
(desktop filter width, collapsed preview readiness and emoji reset). These
same three failures reproduce on unchanged main in the same environment and
are tracked in [Core #92](https://github.com/lapismd/design-core/issues/92).
They remain blocking until repaired or separately accepted; no baseline,
assertion, timeout or product code is changed by this proposal. Activation
therefore remains held.
